| 项目 | 内容 |
|---|---|
| 产品名称 | 随心记 |
| 平台 | iOS（iPhone 优先） |

| 状态 | 草稿 → 待开发 |

> 📖 **什么是 PRD？** Product Requirements Document（产品需求文档）。作用是**动手写代码之前**把"做什么、给谁做、做成什么样"想清楚，开发时照着做，避免边写边改、越改越乱。新手项目失败的第一大原因就是没想清楚就开工。

---

## 1. 产品概述

### 1.1 一句话介绍

**随心记：一款极简的本地日记 App —— 打字、说话、拍照，想怎么记就怎么记。**

### 1.2 要解决的问题

| 用户的痛点 | 随心记的解法 |
|---|---|
| 打字麻烦，日记总是坚持不下来 | 按住说话，语音自动转成文字 |
| 有些情绪文字表达不出来 | 直接录一段语音日记，保留声音本身 |
| 照片散落在相册里，没有当时的心情 | 图片 + 文字放进同一篇日记 |
| 大而全的日记 App 功能太多、太重 | 只做"记录和回看"这一件事 |

### 1.3 竞品参考（学什么、不学什么）

| 竞品 | 值得借鉴的点 | 我们第一版不做的 |
|---|---|---|
| **Apple 手记（Journal）** | 极简界面、打开即写、系统级流畅感 | "回顾建议"推荐算法 |
| **Day One** | 时间轴卡片流、右下角悬浮 ➕、文字/图片/音频混排 | 多日记本、付费订阅、跨端同步 |
| **格志日记（Grid Diary）** | 用提示问题降低"不知道写什么"的门槛 | 模板系统（P2 再考虑） |
| **Daylio / Moo 日记** | 心情打卡，一个 emoji 记录当天情绪 | 心情统计图表（P1/P2） |

> 💡 一个好消息：语音优先（voice-first）的日记 App 正是当下的流行方向，"说话即记录 + 设备端转文字"这个定位不过时。

### 1.4 设计原则

1. **功能做减法**：每加一个功能前先问"没有它能不能记日记？"能，就砍掉或推迟。
2. **3 秒开始记录**：从打开 App 到开始输入，不超过 3 秒、2 次点击。
3. **数据完全本地**：不要账号、不要服务器，隐私和开发难度都最低。

> 📖 **什么是 MVP？** Minimum Viable Product（最小可用产品）。先把最核心的功能跑通、自己能用起来，再一版一版加功能。本 PRD 的 P0 部分 = MVP。

## 2. 目标用户

### 2.1 用户画像

主要用户：**18–35 岁、有记录欲望但难以坚持的普通人**。不追求专业写作，追求"随手、无压力"。

| 画像 | 特点 | 最常用的功能 |
|---|---|---|
| 小林，24 岁，上班族 | 通勤路上想记点东西，单手打字不方便 | 🎤 语音转文字 |
| 阿May，20 岁，大学生 | 爱拍照，希望照片旁边有当时的心情 | 🖼️ 图片 + 短文字 |
| 老周，32 岁，程序员 | 睡前复盘一天，打字快但懒得开电脑 | ⌨️ 纯文本 |

### 2.2 典型使用场景

| 场景 | 时间/地点 | 用户行为 | 用到的功能 |
|---|---|---|---|
| 通勤速记 | 早 8 点，地铁上 | 按住说话 30 秒，转成文字，顺手改两个错字 | 语音转文字 |
| 情绪宣泄 | 晚 11 点，床上 | 不想打字，录 2 分钟语音，选个 😔 | 语音日记 + 心情 |
| 记录出游 | 周末，景点 | 拍 3 张朝霞照片，配一句话 | 图片 + 文本 |
| 睡前回看 | 晚上 | 划一划时间轴，点开上周的日记听当时的录音 | 列表 + 详情 |

## 3. 核心功能

> 📖 **什么是 P0 / P1 / P2？** 优先级标记。**P0 = 没有就不能上线**（第一版必须做）；**P1 = 第二版尽快加**；**P2 = 以后有空再说**。新手最重要的纪律：**只做 P0，做完能用了再碰 P1。**

### 3.1 功能总清单

| 编号 | 功能 | 优先级 | 一句话说明 |
|---|---|---|---|
| F1 | 纯文本日记 | **P0** | 新建 / 编辑 / 删除文字日记 |
| F2 | 语音转文字 | **P0** | 按住说话，实时转成文字填入正文 |
| F3 | 语音日记（录音） | **P0** | 录一段音频存进日记，可回放 |
| F4 | 添加图片 | **P0** | 相册选择或拍照，每篇最多 9 张 |
| F5 | 时间轴列表 | **P0** | 首页按时间倒序展示所有日记 |
| F6 | 详情 / 编辑 / 删除 | **P0** | 查看完整内容、播放语音、看大图 |
| F7 | 心情打卡 | P1 | 每篇日记选一个心情 emoji |
| F8 | 关键词搜索 | P1 | 按正文内容搜索日记 |
| F9 | 日历视图 | P1 | 按月历查看哪天写了日记 |
| F10 | 每日提醒 | P1 | 每天固定时间推送"该写日记啦" |
| F11 | iCloud 同步 | P2 | 换手机数据不丢 |
| F12 | FaceID / 密码锁 | P2 | 打开 App 需要验证 |
| F13 | 导出 PDF / 图片 | P2 | 把日记导出分享或备份 |
| F14 | 标签 / 天气 / 位置 | P2 | 更丰富的元信息 |

### 3.2 P0 功能详细说明

#### F1 纯文本日记

- **怎么用**：点首页右下角 ➕ → 进入写日记页 → 输入文字 → 点"保存"→ 回到首页，新日记出现在最顶部。
- **规则**：
  - 日记的"归属日期"默认是今天，可以点日期改成别的日子（补记昨天的日记）。
  - 文字、图片、录音**至少有一样**才允许保存，全空时"保存"按钮置灰。
  - 字数不设上限；不做加粗/斜体等富文本（保持简单）。

#### F2 语音转文字

- **怎么用**：写日记页底部工具栏点 🎤 → 开始说话，识别出的文字**实时出现在光标位置** → 再点一下停止。转出来的文字和手打的文字没有区别，可以继续修改。
- **规则**：
  - 首次使用会弹出系统权限弹窗（麦克风 + 语音识别），**必须在 Info.plist 写清楚用途文案**，否则 App 会直接闪退（新手最常见的坑之一）。
  - 用户拒绝过权限后再点 🎤：弹提示"需要麦克风权限"，附"去设置"按钮跳转系统设置。
  - 优先使用**设备端识别**（离线可用、不耗流量、隐私好）。

#### F3 语音日记（录音）

- **怎么用**：写日记页点 🎙️ → 开始录音，界面显示计时（如 00:35）和简单的声波动画 → 再点一下结束 → 正文下方出现一条"录音条"（▶ 播放 / 时长 / ✕ 删除）。
- **规则（第一版简化）**：
  - **每篇日记最多 1 条录音**；想重录先删掉旧的。（想扩展成多条，把数据模型里的字段改成数组即可，见第 5 章。）
  - 单条录音最长 **10 分钟**，到时自动停止并保存（防止文件过大）。
  - 录音过程中来电话或 App 切到后台：**自动停止并保存已录的部分**，不能让用户白录。
  - 文件格式：`.m4a`（AAC 编码，体积小、系统原生支持）。

#### F4 添加图片

- **怎么用**：写日记页点 🖼️ → 弹出选项"从相册选择 / 拍照" → 选好后以九宫格缩略图显示在正文下方 → 点某张图右上角 ✕ 可删除。
- **规则**：
  - 每篇最多 **9 张**。
  - 保存时把图片**压缩到长边 ≤ 2048px** 再存（不然几十篇日记就占几个 G）。
  - 图片存进 App 自己的沙盒目录，**不改动、不删除**用户系统相册里的原图。
  - 选相册用系统的 `PhotosPicker`，好处是不需要申请相册权限弹窗；拍照需要相机权限。

#### F5 时间轴列表（首页）

- **展示**：按时间**倒序**（最新在最上面），按"年-月"分组显示分隔标题（如"2026 年 7 月"）。
- **每张卡片显示**：日期 + 星期、正文前 2 行摘要、第一张图片的缩略图（有图时）、🎙️ 角标（有录音时）、心情 emoji（P1）。
- **空状态**（一篇日记都没有时）：显示一句引导文案，如"记录今天的第一条心情吧 →"，并用箭头指向 ➕ 按钮。空状态是新手最容易忘做的页面。
- 本地数据无需"下拉刷新"。

#### F6 详情 / 编辑 / 删除

- **详情页显示**：完整正文、图片（点击横滑看大图）、录音播放条（播放 / 暂停 / 进度 / 时长）。
- **右上角"···"菜单**：编辑（进入写日记页并回填内容）/ 删除。
- **删除规则**：必须弹二次确认"删除后不可恢复，确定吗？"；确认后**同时删除**该日记关联的图片文件和音频文件（否则会留下垃圾文件占空间）。

### 3.3 第一版明确不做的（写下来防止手痒）

账号注册登录、任何服务器/云端、社交分享、富文本排版、多日记本、AI 总结、桌面小组件。—— 全部不做，第一版的敌人是复杂度。

## 4. 界面 UI 设计

### 4.1 整体风格

- **参考 Apple 手记 + Day One**：原生 iOS 味道、大量留白、内容为主、几乎没有装饰。
- **深色模式**：跟随系统自动切换（SwiftUI 用系统语义颜色基本免费获得，别写死颜色值）。
- **字体**：系统默认（中文苹方 / 英文 SF Pro），正文 17pt，摘要 15pt。
- **主题色**：暖橙色 `#FF8A5C`（有"日记本"的温暖感，可自行替换），用于 ➕ 按钮、录音状态等强调处。
- **尺寸规范**：卡片圆角 16pt，页面左右边距 16pt，卡片间距 12pt。
- **图标**：全部用 **SF Symbols**（苹果自带的免费图标库，`Image(systemName: "mic.fill")` 一行代码搞定，不用找设计师）。

### 4.2 页面结构（一共 4 个页面，不用 TabBar）

功能少就不要塞 TabBar，导航越浅越好：

```
首页（时间轴列表）
 ├── 点右下角 ➕ ──→ 写日记页（从底部弹出 sheet）
 ├── 点某张卡片 ──→ 详情页（右滑推入 push）
 │                    └── 点"编辑" ──→ 写日记页（回填内容）
 └── 点右上角 ⚙️ ──→ 设置页
```

### 4.4 关键交互细节

- **➕ 按钮**：点按直接进写日记页。（P1 可升级为长按弹出"文字 / 语音 / 拍照"三个快捷入口，Day One 的经典交互。）
- **保存后**：sheet 收起回首页，新卡片带轻微插入动画出现在顶部——即时反馈让人有"记下来了"的满足感。
- **内容为空点保存**：按钮置灰不可点，占位文案提示。
- **编辑中点"取消"且内容有改动**：弹"放弃本次修改？"确认，防误触丢内容。
- **录音中**：🎙️ 图标变主题色 + 呼吸动画，界面顶部常驻计时，让用户始终知道"正在录音"。

## 5. 数据存储设计

### 5.1 总原则：全部本地，数据库和大文件分开放

| 数据类型 | 存哪里 | 为什么 |
|---|---|---|
| 文字、日期、心情、文件名等"小数据" | **SwiftData** 数据库 | 苹果官方框架，和 SwiftUI 是原配，代码量最少 |
| 图片、录音等"大文件" | App 沙盒的 **Documents 文件夹** | 大文件塞进数据库会让列表越滑越卡 |

> 📖 **SwiftData 是什么？** 苹果官方的本地数据库框架（iOS 17+）。你用一个 Swift 类描述数据长什么样（加个 `@Model`），增删改查它全帮你做，视图里用 `@Query` 一行代码就能拿到数据并自动刷新。新手做本地 App 的最省心选择。
>
> ⚠️ **新手铁律：数据库里只存文件名，不存文件本身。** 真实的图片/音频放文件夹里，数据库记录 `"a1b2c3.jpg"` 这样的名字，用的时候拼路径去读。

### 5.2 数据模型（只需要一张"表"）

**DiaryEntry（一篇日记）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 唯一标识，自动生成 |
| `createdAt` | Date | 创建时间（列表排序用它） |
| `diaryDate` | Date | 日记归属的日期（默认 = 创建当天，用户可改，用于补记） |
| `updatedAt` | Date | 最后编辑时间 |
| `text` | String | 正文，可为空字符串 |
| `mood` | String? | 心情 emoji，如 "😊"，可为 nil（P1 功能，字段先留着） |
| `imageFileNames` | [String] | 图片文件名数组，如 `["9F2A….jpg"]`，无图为空数组 |
| `audioFileName` | String? | 录音文件名，没录音为 nil |
| `audioDuration` | Double? | 录音时长（秒），用于列表/播放条显示 |

对应的 SwiftData 代码大概长这样（真实开发时以此为准微调）：

```swift
import SwiftData

@Model
final class DiaryEntry {
    var id: UUID = UUID()
    var createdAt: Date = Date()
    var diaryDate: Date = Date()
    var updatedAt: Date = Date()
    var text: String = ""
    var mood: String? = nil
    var imageFileNames: [String] = []
    var audioFileName: String? = nil
    var audioDuration: Double? = nil

    init() {}
}
```

### 5.3 文件目录规划

```
App 沙盒/Documents/
├── images/
│   ├── 9F2A41B7.jpg      ← 用 UUID 命名，避免重名覆盖
│   └── 1C88D0E2.jpg
└── audios/
    └── 7C11A93F.m4a
```

- **写入时机**：点"保存"时才把图片压缩写入、把临时录音移入 `audios/`；点"取消"则清理临时文件。
- **删除日记**：写一个统一的 `deleteEntry()` 函数——**先删关联文件，再删数据库记录**，保证不留垃圾文件。

### 5.4 为什么第一版不做 iCloud 同步（重要）

1. SwiftData 开 CloudKit 同步需要**付费开发者账号**（¥688/年）和额外配置，对新手是一连串坑；
2. 图片、音频这类大文件的云同步需要自己额外处理，复杂度陡增；
3. 先把本地跑通，P2 再加，届时数据模型不用大改。

⚠️ **必须告知用户的风险**：本地存储意味着**删除 App = 数据全部丢失**。要在设置页写清楚这句话。这不是可选项，是对用户（包括未来的你自己）的基本诚实。

## 6. 权限与系统能力清单

| 功能 | 用到的系统框架 | 需要在 Info.plist 声明的权限 |
|---|---|---|
| 语音转文字 (F2) | Speech | `NSSpeechRecognitionUsageDescription` + `NSMicrophoneUsageDescription` |
| 录音 (F3) | AVFoundation | `NSMicrophoneUsageDescription` |
| 相册选图 (F4) | PhotosUI 的 `PhotosPicker` | 不需要权限描述（系统代管，iOS 16+） |
| 拍照 (F4) | 相机 | `NSCameraUsageDescription` |
| 每日提醒 (F10, P1) | UserNotifications | 运行时向用户请求即可 |

**权限文案示例**（写得具体，用户才愿意点允许，审核也要求写清用途）：

> 麦克风："随心记需要使用麦克风来录制语音日记和语音转文字。"
> 语音识别："随心记需要语音识别权限，把你说的话转换成日记文字。"
> 相机："随心记需要使用相机为日记拍摄照片。"

## 7. 技术选型（新手版）

| 用途 | 选什么 | 为什么 |
|---|---|---|
| UI 框架 | **SwiftUI** | 官方主推、声明式写法、教程最多 |
| 本地数据库 | **SwiftData** | 与 SwiftUI 天然配合，样板代码最少 |
| 语音转文字 | **Speech 框架（SFSpeechRecognizer）** | 系统自带、免费、支持设备端中文识别；iOS 26 有更新的 SpeechAnalyzer API，但 SFSpeechRecognizer 教程多得多，新手先用它 |
| 录音 / 播放 | **AVFoundation**（AVAudioRecorder / AVAudioPlayer） | 系统自带，几十行代码搞定 |
| 相册选图 | **PhotosPicker（PhotosUI）** | SwiftUI 原生组件，免权限弹窗 |
| 最低系统版本 | **iOS 17**（SwiftData 的硬要求） | 只给自己用可直接设 iOS 18+ |
| 第三方库 | **一个都不用** | 第一版全用系统能力，少一个依赖少一个坑 |

> 💡 **架构建议**：新手不要纠结 MVVM / TCA 这些名词。就用 SwiftUI 默认写法：`@Model` 定义数据 + `@Query` 在视图里取数据 + 几个小的工具类（如 `AudioRecorder`、`FileStore`）。等 App 能用了再谈重构。

## 8. 开发计划（阶段 + 验收标准）

每个阶段有明确的**验收标准（✅）**——不达标不进入下一阶段，这是防止"到处都是半成品"的关键纪律。

| 阶段 | 时间 | 做什么 | ✅ 验收标准 |
|---|---|---|---|
| **Phase 0 · 项目搭建** | 1–2 天 | 建 Xcode 工程、配好 SwiftData、能存取一条假数据 | 杀掉 App 重开，假数据还在 |
| **Phase 1 · 文本闭环** | 第 1 周 | F1 + F5 + F6：纯文本的新建 / 列表 / 详情 / 编辑 / 删除 | 全流程走 10 遍无崩溃；删除有二次确认 |
| **Phase 2 · 图片** | 第 2 周 | F4：选图 / 拍照 / 压缩存储 / 九宫格 / 大图浏览 | 存 3 张图后重启 App 图片正常显示；删除日记后 `images/` 里对应文件消失 |
| **Phase 3 · 语音** | 第 3 周 | F2 + F3：语音转文字、录音、播放、权限引导 | 开飞行模式语音转文字仍可用；拒绝权限后有"去设置"引导；录音中切后台不丢已录内容 |
| **Phase 4 · 打磨** | 第 4 周 | 空状态、深色模式检查、App 图标、启动图、（可选 F7 心情） | 自己真实使用 3 天，没有想砸手机的瞬间 😄 |

> 💡 两条实践建议：① 每个 Phase 结束都装到**真机**上跑一次（语音和相机在模拟器上不完整），别攒到最后；② 开工前花 10 分钟做个"事前验尸"——想象一个月后项目失败了，最可能的原因是什么？把答案写下来重点防范（大概率是"Phase 1 没做完就去玩语音了"）。

## 9. 边界情况与风险（提前想好，少踩一半的坑）

| 情况 | 怎么处理 |
|---|---|
| 用户拒绝了麦克风 / 语音识别权限 | 点 🎤/🎙️ 时弹提示 + "去设置"按钮跳系统设置 |
| 录音中来电话 / 切到后台 | 自动停止并保存已录部分 |
| 设备不支持离线语音识别 | 提示"需要联网使用语音转文字" |
| 手机存储空间不足，写文件失败 | 保存失败给出明确提示，不要静默丢数据 |
| 日记内容全空 | 禁止保存（按钮置灰） |
| 用户误删日记 | 删除前二次确认（第一版不做回收站） |
| 图片特别大（如 4800 万像素原图） | 保存时统一压缩到长边 ≤ 2048px |
| 用户修改了手机系统时间 | 排序用 `createdAt`，展示日期以用户选的 `diaryDate` 为准 |
| 正在播放录音时用户删除了这篇日记 | 先停止播放，再执行删除 |

## 10. 成功标准（给自己定的小目标）

1. **上线自用**：自己连续记录 **7 天**（产品最重要的检验：作者自己愿不愿意用）。
2. **速度**：从打开 App 到开始输入 ≤ 3 秒、≤ 2 次点击。
3. **稳定**：自用期间 0 崩溃。
4. （可选）通过 TestFlight 发给 2–3 个朋友，收集 3 条真实反馈再决定 P1 做什么。
